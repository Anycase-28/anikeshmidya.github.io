Engineering approach

Understand the system before changing it.

Especially in inherited or government systems, the fastest route to a correct fix is usually disciplined investigation rather than rewriting code prematurely.

01

Trace the flow

Follow the request from UI to API, application logic and database before changing behaviour.

02

Respect existing contracts

Preserve established interfaces, component names and operational expectations unless change is justified.

03

Fix the root cause

Separate symptoms from configuration, authentication, data and application defects.

04

Document what matters

Make APIs, workflows and operational steps understandable to both developers and users.
